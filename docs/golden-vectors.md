# Golden-vector fixture-format freeze (A.13 / plan §10.7 / P4)

**Status: FROZEN as of Stage A.** This document pins the **fixture format**
that both halves of the parity harness consume — the Stage C live signal
engine (Phase 23) and the Stage D replay engine (Phase 30) read **one harness,
one format**. Changing this format after Stage A requires a PR that updates
both consumers and regenerates every fixture in the same change.

What is frozen here is the *format only* — **not** `strategy-schema/v1`
(designed in Stage C / Phase 18, frozen at the Stage C exit gate; D18
versioning covers later evolution), and **not** the composite formula
(ADR amendment A1; lands with the engine in Stage C / Phase 20).

## 1. Fixture directory layout

```
libs/strategy-engine/src/test/resources/golden/
├── candles/
│   ├── README.md                 # generation seed + generator version, recorded once
│   ├── NSE_NIFTY50_1m_day1.csv   # five trading days of synthetic 1m NIFTY candles
│   ├── NSE_NIFTY50_1m_day2.csv   #   … generated ONCE by the seeded mock generator,
│   ├── NSE_NIFTY50_1m_day3.csv   #   then committed and never regenerated
│   ├── NSE_NIFTY50_1m_day4.csv
│   └── NSE_NIFTY50_1m_day5.csv
├── strategies/
│   └── <feature>.yaml            # one strategy YAML per schema feature
└── expected/
    ├── <feature>.signals.json    # expected-signal vectors (parity family)
    └── <feature>.metrics.json    # expected-metrics vectors
```

- **Candle fixtures are write-once.** They are generated by the seeded mock
  generator (Phase 7's deterministic feed, replayed through the 1m candle
  builder) and then **frozen** — regeneration is a format-breaking event.
- One strategy YAML per `strategy-schema/v1` feature, named for the feature it
  exercises (e.g. `optional-indicator-activation.yaml`).

## 2. Candle encoding

CSV, header row required, one row per 1m bucket:

```
exchange,tradingsymbol,interval,bucket,open,high,low,close,volume
NSE,NIFTY 50,1m,2026-01-05T09:15:00+05:30,21750.05,21752.40,21748.95,21751.10,0
```

- **Prices are exact decimal strings** — never floats; parsers must read them
  into `BigDecimal` (Java) / `Decimal` (Python tooling) without a double hop.
- **Bucket key** is the IST bucket start, ISO-8601 with the explicit `+05:30`
  offset (`TIMESTAMPTZ` semantics). Buckets are left-closed minute floors.
- Identity is `(exchange, tradingsymbol)` — never numeric instrument tokens.
- `interval` is the literal `1m` for these fixtures.
- `volume` is the per-bucket traded volume (derived from cumulative day volume
  per A.7.2; `0` is legal for index fixtures).

## 3. Expected-signal encoding (the parity family)

`expected/<feature>.signals.json` pins the signal list that **both** the
tick-wise live path and the replayed backtest path must produce
**byte-identically** after canonical JSON serialization:

```json
{
  "fixtureFormat": 1,
  "strategy": "optional-indicator-activation.yaml",
  "candles": ["NSE_NIFTY50_1m_day1.csv", "..."],
  "signals": [
    {
      "timestamp": "2026-01-05T10:42:00+05:30",
      "exchange": "NSE",
      "tradingsymbol": "NIFTY 50",
      "direction": "LONG",
      "composite": "0.7421",
      "breakdown": {
        "rsi": { "score": "0.8000", "weight": "0.5000", "activated": true },
        "macd": { "score": "0.6500", "weight": "0.5000", "activated": true }
      }
    }
  ]
}
```

- Timestamps: ISO-8601 IST `+05:30`, minute-bucket aligned.
- All scores/weights/composites: **exact decimal strings** (scale fixed by the
  engine at emission; comparison is string equality, not numeric tolerance).
- The per-indicator breakdown is part of the frozen vector (the BPB
  score-breakdown contract pins exactly this and nothing else).
- Canonical serialization: UTF-8, keys in the order shown, no insignificant
  whitespace differences (the harness serializes both sides through the same
  writer before comparing bytes).

## 4. Expected-metrics encoding

`expected/<feature>.metrics.json` pins backtest metrics as **exact decimal
strings**:

```json
{
  "fixtureFormat": 1,
  "strategy": "optional-indicator-activation.yaml",
  "metrics": {
    "returns": "0.0312",
    "sharpe": "1.4210",
    "maxDrawdown": "-0.0125",
    "winRate": "0.6250",
    "tradeCount": "16"
  }
}
```

- The five pinned metric keys are `returns`, `sharpe`, `maxDrawdown`,
  `winRate`, `tradeCount`; additive keys are allowed later, renames are not.
- Version-immutability checks re-derive the stored **SHA-256 checksum** of the
  canonical fixture bytes; a checksum mismatch fails the suite.

## 5. Invariants (the contract the suite enforces)

1. Same YAML + same candles ⇒ **identical signals and metrics, live and
   backtest** (byte-identical after canonical serialization).
2. No floats anywhere in fixtures or comparisons.
3. Fixtures are immutable once committed; a format change bumps
   `fixtureFormat` and regenerates everything in one PR.
