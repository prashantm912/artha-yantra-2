## Open doubts

- **Rerun confirmation:** rerun submits directly from Jobs and shows a success toast, rather than routing through the runner's confirmation dialog. This is the brief's explicitly allowed cheaper path. A legacy row missing any required request field disables Rerun with an explanatory title instead of sending a fabricated request.
- **Clone transport/seeding:** clone uses React Router state `{ clone: Partial<RunRequest> }`; the runner reads that state in its initial state functions and seeds all available fields. Router state is intentionally not a durable/shareable URL, so a hard refresh after navigation can lose the clone payload.
- **Sweep rerun:** optimization/sweep rerun remains scoped out; Rerun and Clone controls render only for `kind === 'BACKTEST'`.
- **Optimizer list envelope:** the consumed response is `{items, limit, offset}`. Each item projects `jobId`, `status`, `progress`, `error`, `createdAt`, `strategyId`, `method`, `objective`, `from`, and `to`. It does not project a raw `trialsCompleted` count, so the page labels the authoritative percentage as "Trials complete" and renders the projected `error` under "Failure reason".
- **Accessibility:** confirmation uses the existing Radix dialog with title, description, focus trap, real Cancel/Confirm buttons, and explicit focus return. Rerun/Clone have row-specific accessible names and sweep IDs are links. Component role/name tests passed, but no manual browser/axe pass was run because the brief forbids starting the stack.
- `npm ci` reported three moderate dependency vulnerabilities. They were not changed because lockfile/security remediation is outside the authorized scope.
- The tiny backend echo has no new dedicated test because the hard path boundary permits only the controller on the backend; the full 348-test verify plus contract and Map-ratchet tests are the available regression evidence.
