## §Dow — the flag was the wrong wire, and the right one was already live (2026-08-01)

**Verdict: `ARTHA_OPENALGO_GLOBAL_QUOTES_ENABLED` can never feed the Dow dot on this stack. Arming it
would have produced a failing HTTP call that degrades to the same NEUTRAL, silently.** The owner's ask
("OpenAlgo appliance joins live stack") was executed — the appliance is up and healthy — but the goal it
was meant to serve needs a different implementation, now being built.

### Why the OpenAlgo path cannot work here
- The only `GlobalQuoteSource` implementation POSTs `{"symbol":"DOWJONES","exchange":"GLOBAL_INDEX"}`
  (`OpenAlgoGlobalQuoteClient`, via `OpenAlgoExchange`'s verbatim pass-through — `GLOBAL_INDEX` is not in
  the INDEX remap table).
- `GLOBAL_INDEX` is an **Upstox instrument-key segment** (`UpstoxGlobalInstrument.java:18`), not an
  OpenAlgo exchange; the real key form is `GLOBAL_INDEX|^DJI`, not `DOWJONES`. The request is malformed
  for either backend.
- Three independent in-repo statements gate this path on an **Upstox-backed** appliance:
  `GlobalQuoteSource.java:9`, `OpenAlgoConfig.java:103-104`, `docs/manual-tests/data-foundation-activation.md:56`.
  **Ours fronts Zerodha** (`deploy/openalgo/README.md:39-50`), and Indian brokers do not serve US indices.
- Empirical check was **inconclusive by design**: both `DOWJONES/GLOBAL_INDEX` and a `NIFTY/NSE_INDEX`
  control returned 500 against the live appliance, because no broker session exists yet. The code
  evidence stands on its own; the probe is worth repeating after login only to close it out.

### The feed that already works
`ARTHA_UPSTOX_ANALYTICS_ENABLED=true` has been live all along, and `GET /api/v1/market/world-indices`
serves Dow **right now** — probed on the running container 2026-08-01 13:22 IST:

```
{"name":"DOW JONES","country":"America","key":"GLOBAL_INDEX|^DJI","tradingSymbol":"^DJI",
 "ltp":"52548.91","prevClose":"52229.06","netChange":"319.85","changePct":"0.61",
 "asOf":"2026-08-01T13:22:11.29+05:30","latency":"20 Seconds"}
```

`ltp` + `prevClose` are exactly the two fields `ConnectingDotsService.dowFactor` reads
(`ConnectingDotsService.java:325-332`). **Nothing joined that feed to `GlobalQuoteSource`** — that is the
whole defect. Build in flight: a second `GlobalQuoteSource` backed by this path, mutually exclusive with
the OpenAlgo one, behind its own default-OFF flag.

### Why it ships default-OFF
The Dow dot currently contributes NEUTRAL to **every** composite row. Making it real changes which
signals fire — HOLD tier by the ledger's own rules — so the PR lands unarmed and arming is a separate
decision after forward measurement, matching the G13 dead-dot doctrine the owner approved the same day.

### The silent-failure lesson (worth more than the fix)
`OpenAlgoGlobalQuoteClient.java:28-32` swallows every `RuntimeException` into `Optional.empty()`, and
`dowFactor` maps that to NEUTRAL — **no log, no metric, no alert.** A weight-1.0 input was dark for months
and every health surface stayed green. This is the same blindness class as ledger row G16 (live, moving,
never crossing). The build adds a WARN + counter on the degradation path for both implementations; the
fail-soft behaviour itself is correct and stays.

### Still owner-gated
The appliance has **no broker session** — login is an OAuth flow against your own brokerage account, at
`http://127.0.0.1:5001`. Nothing on the OpenAlgo path (including the already-`true`
`ARTHA_OPENALGO_OI_BACKFILL_ENABLED`, currently dormant — zero OpenAlgo log lines in 24h) does anything
until that happens. **The Dow fix does not depend on it.**
