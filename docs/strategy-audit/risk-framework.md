# Risk Framework Audit — Global Risk Management (Section 2)

**Scope:** Audits Section 2 (2.1–2.14) of `strategy-documents/options-scalper-siva/Options_Scalper_Siva_Consolidated_Strategy.md` — the global, strategy-agnostic risk rails (RR ratio, per-trade sizing, daily loss cap, 5-account split, hard SL, no-averaging, trend/time filters, capital preservation) — against the scalper automation: `ScalperRisk`, `ScalperAccountModel`, `RiskService` + the `V006__paper_account_risk` schema, `ScalperGates`, `ScalperConfig`, the engine `PositionSizer`, and the scalper YAML `risk:` block. Verdict in one line: **the *structural* rails are automated (hard-SL refusal, single-position-per-symbol, 5-account/5-win discipline, time-window gate), but every *numeric* money-management threshold the doc states (1:2 RR, 0.5%/2-3%/10-12% loss caps, 10-20% per-trade cap, 5-10%-of-capital allocation, winning=losing qty, index-scaled point SLs) is either NOT enforced as a number, disabled-by-default, or left to the human** — and several documented psychological/process rules are not in the manual checklist either.

## Not automated (gaps)

- **1:2 RR / 0.5%-risk:1%-reward (r1–5)** — no RR target and no 0.5%-of-equity per-trade risk; scalpers size by a fixed `budget_inr` and carry no `take_profit`. **Highest-value automatable gap** (compute target = entry ± 2×stop-distance; switch to `atr_risk` 0.5%).
- **All percentage money-management caps are NOT coded numbers:** the ≤10–20%-per-trade / ≤20%-per-day deployment cap (r6), the 5–10%-of-capital allocation (r54), and the 1–2% daily profit target (r14) have no rail at all.
- **The 0.5% / 2–3% / 10–12% daily LOSS caps are disabled by default** — `V006__paper_account_risk.sql` seeds `paper_account` but NO `risk_settings` row, so `daily_loss_limit` / `kill_switch` / `max_open_paper_positions` are all OFF until the owner sets them in the Settings panel. The doc's headline "0.5% rule" and "2–3%" and "10–12%" thresholds are not pre-seeded.
- **`risk.max_daily_loss_pct: 2.0` in every scalper YAML is a DEAD key** — schema-validated (`strategy-schema-v1.json:552`) but never read by `StrategyCompiler` (only `position_sizing` + `session` are compiled), so it enforces nothing.
- **Index-scaled point stop-losses (Nifty ~30–60 / Sensex ~200–250 / BankNifty ~75, r53/55/64) are not encoded** — stops are structural extremes, with no per-index point band.
- **Scale-in / laddered deployment (r7, r47, r63 geometric 1/2/4/8) and winning-qty=losing-qty symmetry (r9/r44/r49) are absent** — sizing is single-shot and outcome-blind.
- **Recycle-realized-profit-as-next-risk (r10, r67) is absent** — sizing ignores prior P&L despite `dayPnl` being available.
- **VIX/OI-gap-driven position sizing (r65) is absent** — VIX gates only direction, not size.
- **The 5-account model is day-granularity only** (loss/win COUNTS vs 5), not a true per-account capital split with per-account 1% targets and per-account first-loss freeze (r15–19).
- **Process/psychological rules are neither automated nor in the manual checklist:** first-trade-should-win (r18), pre/post-market routine + prerequisites + calm-place (r34–36), journal-required (r37), money-you-can-afford / no-borrowed-funds (r38), survive-a-losing-quarter sizing (r40), backtest-≥1yr-before-deploy publish gate (r42), scale-lots-only-every-3-6-months (r51).
- **Manual-checklist coverage of Section 2 is thin:** of the 7 `ScalperManualChecks` items, only `news_clear`/`vix_normal`/`global_cues_ok`/`clean_setup`/`regime_ok` touch Section-2 rules; there is NO checklist item for "daily profit/loss target set", "risk ≤0.5%/trade", "deployment ≤10–20%", "qty symmetry", or "SL set in the system" — the headline money-management discipline is left entirely to the trader's memory.
