## Trending OI Crossover — automation audit

Scope: audits Siva strategy #5 (Trending OI Crossover) — doc §3.5 (narrative card) and §6.5 (JSON spec) — against
the three `scalp-trending-oi-*.yaml` configs and the shared scalper engine (`ScalperConfluenceGate`, `ScalperGates`,
`ScalperConfig`, `ConnectTheDotsScorer`, `MarketOiClient`, `ScalperOiProps`, `ScalperManualChecks`). This is the ONE
scalper whose defining edge is OI itself: the YAMLs carry the `oi-cross-filter` tag (yaml:12), which arms a HARD
`requireCallPutDeltaFilter` pre-gate — the ≥50% call-vs-put dOI imbalance must clear BEFORE the confluence is consulted
(ScalperConfluenceGate.java:193-199; ScalperGates.callPutDeltaFilter:151-161; default floor 50 in ScalperOiProps.java:32).
The chart YAML gate is only `close > vwma20`; the OI cross, sentiment slope, gap-widening and futures-OI all live in the
Connect-the-Dots confluence seam. **Derived-history caveat:** every OI/sentiment/IV/VIX/breadth dot below degrades to
NEUTRAL on backtests (no real `options_chain_snapshots` pre-2026-06-15; Dow+IV→NEUTRAL), and a `null` imbalance DEGRADES
the cross pre-gate to PASS — so on history the strategy's whole edge is muted. Judge automation by code presence, not
backtest behaviour; value-verify on FORWARD paper with real captured OI.

### Not automated (gaps)

- **Cross is a soft dot, not a hard trigger** — the defining PE-over-CE (long) / CE-over-PE (short) crossover is ONE
  confluence dot (weight 1.0), so a signal can fire on aggregate ≥0.6 without a fresh cross when `gapWidening` + delta
  signs align. The HARD pre-gate is the ≥50% call-put dOI imbalance, not the cross event itself. (PARTIAL → manual:
  confirm a real line cross; automatable as a "crossedThisWindow required" pre-gate.)
- **Flat-OI trap is inverted** — the flat-OI caveat makes the ≥50% imbalance gate `null` → DEGRADE-TO-PASS, the
  opposite of the doc's "stand aside on flat OI" intent. A flat-OI day removes the gate instead of blocking. (PARTIAL —
  automatable: treat null/flat imbalance as a soft stand-aside.)
- **No 1–2% target / no gap-widening trail** — exits are VWMA-break + 12-bar timeout only; the §3.5 "1–2% per scalp"
  target and "ride while the OI gap widens" trail are absent. (NONE/PARTIAL — automatable for the % TP.)
- **Fake-cross side-flip not automated** — the doc's "book SL and switch to the other side where the next genuine cross
  prints" is unmodelled. (PARTIAL — automatable as a side-flip on a confirmed opposite cross.)
- **Failed/incomplete-cross & end-of-series ambiguity unmodelled** — the cross derivation only tests last-vs-first sign,
  so a stalled/reversing in-progress cross (sellers re-writing) and the both-sides-covering series-end case are not
  rejected. (NONE — partially automatable; series-end needs cross-series OI state.)
- **Magnitude thresholds missing** — the ~20–30% immediate-divergence, ≥50%-gap conviction, and "substantial price
  move" corroboration are reduced to a boolean `gapWidening`; no % magnitudes. (PARTIAL — automatable off the same series.)
- **RSI band conflict** — engine uses §4.2 (CE 60–80 / PE 20–40), narrower than the §3.5 card (<75 / >25); the bearish
  RSI is doc-flagged UNCERTAIN (deck >25 vs grid <25). (PARTIAL — reconcile before tuning.)
- **Probability-graded sizing missing** — fixed ₹15,000 premium budget; the §3.5 small-on-low-probability /
  full-on-drastic-shift sizing is not encoded. (PARTIAL — automatable off the confluence aggregate.)
- **Strike housekeeping (reset to ATM ±7 on >1% move), 60-min trend read, direction-change arrows, EOD-OI next-day
  bias** — none modelled. (NONE/PARTIAL — mostly automatable from the OI series; overnight bias is SPAN/positional-gated.)
- **Bearish PE / short legs** — these YAMLs are CE-LONG-ONLY; the CE-over-PE bearish cross (Buy PE) needs a mirror YAML,
  and the "Sell PE / Sell CE" short legs are SPAN/live-order deferred. (PARTIAL.)
- **Monthly-expiry positional+intraday OI confirmation** — the engine SUPPRESSES OI on monthly expiry rather than
  confirming positional vs intraday as §3.5 S21(d) asks. (MANUAL_COVERED via suppression — automatable as a compare.)
