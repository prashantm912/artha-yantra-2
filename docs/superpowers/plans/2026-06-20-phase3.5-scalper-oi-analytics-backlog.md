# Phase 3.5 — Scalper OI-analytics fidelity (deferred backlog)

**Status:** DEFERRED (owner-approved 2026-06-20). Created from the consolidated-doc verification
of the 4 index-option-core scalpers (#1/#5/#6/#10). The **accuracy** defects and the **Tier-1**
structural-completeness gaps were fixed in `bd4f294` + `3dc4c96`; the items below are the **Tier-2**
completeness gaps, all of which need **new market-data OI-analytics** the current endpoints don't
expose (per-side ΔOI, sentiment slope, spurt magnitudes, 6-strike IV pair). They are NOT bugs in the
shipped code — they are the difference between the v1 confluence's coarse OI dots and Siva's full
spec. Source: `strategy-documents/options-scalper-siva/Options_Scalper_Siva_Consolidated_Strategy.md`.

The common root cause: `MarketOiClient` reads **point-in-time absolute** OI levels (and a single
sentiment scalar / ATM IV), while several Siva rules are defined on the **change** of OI over the
trending window, its **slope**, or **per-strike magnitudes**. Closing these is one coherent slice:
extend the market-data OI endpoints to expose the change/magnitude series, then consume them in
`MarketOiClient` → `ScalperGateContext.Oi`/`Macro` → `ConnectTheDotsScorer`/`ScalperGates`.

Engine reality to respect (unchanged): `ConnectTheDotsScorer` is pure/point-in-time (no series
history, no network) — temporal derivations (Δ, slope, cross-event) belong in `MarketOiClient` (it
already iterates the REST envelope), surfaced as derived fields the scorer reads. Degrade-to-pass
discipline holds: when the new data is unavailable, a dot must NOT confirm and must NOT falsely block.

## Suggested sequencing (one market-data slice, then the scorer)

1. **market-data**: extend the OI analytics endpoints to expose the change/slope/magnitude series —
   `/options/trending` per-side ΔOI (or enough bucket history for the client to derive it),
   `/active-strikes` sentiment slope, `/options/spurt` OI%/price% magnitudes, an IV-pair (3+3 CE/PE
   averages). Contract canary + tests per the Kite-wire DTO discipline.
2. **MarketOiClient**: derive the temporal quantities (Δ, slope, cross-event, widening) from the
   series; surface them on `ScalperGateContext.Oi`/`Macro` as derived fields.
3. **ConnectTheDotsScorer / ScalperGates**: consume the new fields — T2.1 as a hard pre-gate for #5
   (its defining edge), T2.6 as a scorer dot, T2.5/T2.7/T2.8 as new/qualified dots. Keep the existing
   dots; do not reweight the frozen `ScoreBreakdown` (scalper fields ride the V009 side-channel).
4. Tests: per-side ΔOI math, the 50% filter, the flat-OI caveat, the slope/spurt/IV-pair dots, and a
   degrade-to-safe path for every new field.
